# 双账号与一起听增强分支

本分支由 baek-nanxun 维护，基于 SPlayer-Dev/SPlayer-Next 的 dev 分支整理，保留上游许可证与版权信息。

## 账号

QQ 音乐可以从主账号入口通过 QQ 或微信扫码登录，与网易云登录态同时保存。当前平台决定首页昵称、喜欢列表、创建和收藏的歌单、会员资料以及在线收藏操作；两个账号可独立退出。

## 一起听

- SPlayer 自建房间：支持 QQ／网易云歌曲，双方播放、暂停、切歌和拖动进度；选歌单自动共享，增删和排序同步；最多 2000 首。双头像与本次时长显示在房间卡片，聊天位于独立侧栏。异地建房可使用双方可达的 Tailscale 地址或独立房间服务
- 网易云官方房间：支持官方分享短链、加入及创建房间，与网易云官方 App 进行播放控制和完整队列同步。当前上限为 2000 首网易云歌曲
- QQ 音乐官方房间：支持官方分享短链、加入及创建房间、真实 MID 与数字 ID／歌曲类型转换、播放控制和完整队列同步；上限为 1000 首 QQ 音乐歌曲

官方模式通过约 2 秒间隔的串行请求读取状态，网络慢时等待当前请求完成，不保证毫秒级同步。各自使用音乐账号获取音源，权限由对应平台决定。官方文字聊天、语音、表情与虚拟形象尚未接入，自建房间保留聊天。

缓冲端单独恢复，准备状态不会变成发给听友的暂停；自动校准只让落后端追赶。官方模式的计时是本次 SPlayer 连接期间的本机估计，不代表平台历史累计时长，无法精确判断官方 App 的缓冲状态。

已在 Linux amd64 与官方 App 进行人工联调：官方 App 建房并由 SPlayer 加入、双方播放控制、保持完整队列，以及 SPlayer 建房并由 QQ 官方 App 加入。尚未完成 Windows／macOS 的人工验证。

## 维护与贡献

本 Fork 独立维护增强功能，当前不向上游提交 PR。默认 dev 分支提供整合源码，codex/qq-and-together-enhanced 分支保存本次增强版本，方便与上游对照。本分支包含本机网易云网络兼容适配，未关闭证书与主机名校验。

使用 AI 辅助开发，提交前进行代码审阅、自动化检查与上述 Linux 人工联调；尚未实测的平台和接口限制如实保留在本页。

2026 年 10 月 27 日，本次基于上游 dev 的整合源码通过 573 项 Vitest 测试、90 项 Node 测试、node／web 类型检查、全库 ESLint、改动文件格式化与 electron-vite 构建。原生模块未改动，本次未重新编译 Rust 或验证其他平台安装包。

从 1.2.2 开始，安装包与应用检查更新均使用本 Fork 的 Releases。旧版仍使用上游更新地址，需要先手动安装一次 1.2.2 或更新的增强版；之后可以在应用内检查增强版更新。

- 自建房间统一管理随机顺序与单曲循环，两端显示相同模式；自然结束沿共享随机顺序切歌，关闭随机恢复原列表
- 新建网易云官方空房间后点击本机当前歌曲，先提交完整本机列表；空队列、平台不匹配和编号异常分别提示
- 网易云房间请求使用独立的有界连接池和十五秒超时；只读查询临时失败时重试一次，写控制不自动重放；短暂同步中断保留本机播放，恢复后重新上报准备状态

双方都需要更新后重新创建自建房间；使用独立房间服务时，也需更新对应服务脚本。官方房间的随机／循环模式尚未接入协议，界面会明确提示使用自建房间，不会只在本机切换后又被快照重置。

本次验证：585 项 Vitest 测试、94 项 Node 测试、类型检查、ESLint 和应用构建通过。两个真实 Linux 播放器使用隔离资料联调，确认封面解码显示、点击发送只产生一条消息、随机自然切歌进入实际音频播放、关闭随机恢复顺序。网易云双端互控和超时恢复使用模拟官方接口验证；本次未重新进行异地双账号人工联调。

内存记录来自启动后一分钟的日志：修复前 Browser／GPU／Network／主界面分别为 378／331／84／246 MB，修复后为 384／349／83／239 MB。修复后样本已执行播放和聊天联调再回首页，属于单次采样，不代表长期内存趋势。

源码与构建方式沿用上游 README 和 package.json。账号 Cookie、用户数据库、私人房间邀请、测试配置与本地备份不属于仓库内容。QQ 协议字段参考 qmtui，对应 MIT 许可保留于 THIRD_PARTY_NOTICES/qmtui-LICENSE.txt。

## 1.2.3 首页历史封面修复

首页「反复聆听」使用最新播放快照，并从同平台、同歌曲 ID 的历史记录补齐缺失的封面和专辑。早期一起听保存的简化快照不再遮掉已经存在的封面；播放次数、时长和时间均不改写。播放过程中晚到的封面元数据也会保存到当前统计会话，不会多记一次播放。没有任何历史封面数据的歌曲仍显示占位图。

这与上游 [Issue #306](https://github.com/SPlayer-Dev/SPlayer-Next/issues/306) 的本地 FLAC 内嵌封面 MIME 字段问题不同，不需要修改音乐文件。

## 1.2.4 账号显示与 QQ 空房间

QQ 与网易云头像旁的会员标识采用相同的响应式规则：宽窗口显示，窄窗口隐藏，展开账号面板后始终保留会员资料。

QQ 官方一起听现在可以先创建空房间，再邀请听友、选择歌曲或歌单播放，不需要提前播放歌单。空房保持暂停，首次加入歌曲后恢复暂停状态，主动播放才开始同步。已实测官方服务接受零首歌曲建房、读取空队列、加入首曲及退出；空房邀请与 QQ 官方 App 的双账号人工加入仍待补充验证。

QQ 取源失败日志增加 HTTP 状态、平台返回码和是否携带登录凭据，便于排查跨设备差异，不输出 Cookie、密钥或签名播放链接。连续空地址触发的凭据刷新限制为同账号每分钟最多一次，并合并并发刷新，避免无可用地址时逐首重复刷新。日志可在设置 → 关于 → 打开日志查看；这不会改变账号的歌曲权限，也不代表所有 Windows 空地址情况已修复。

本次通过 596 项全库 Vitest 与 5 项新增取源诊断和刷新限流测试、94 项 Node 测试、类型检查、ESLint 和生产构建。账号显示的六项实际布局检查在 Xvfb 隔离显示环境完成。

## 1.2.5 房间恢复与聊天提醒

QQ 官方房间只固定音乐账号身份，同账号续期登录密钥不再被误判为换号。单次房间不可用先进入重连，连续三轮确认不可用后才结束同步；不会自动建房或重新发送播放指令。心跳异常写入不含邀请与凭据的诊断日志。

退出先清理本机连接和排队控制，再等待官方退房确认。官方请求失败也能恢复单人播放，界面会明确提示尚未确认服务端退房，避免界面一直留在房间中。晚到心跳不能把已退出的房间恢复。

一起听不再把所有歌曲加载失败都提示为会员权限问题：官方空地址、网络异常和音频加载错误分别保留原原因。QQ 取源显式附带当前账号的认证字段；这不会扩大账号权益，也不能据此保证受限的歌曲版本可播。

自建房间聊天入口增加未读红点，收到对方新消息时显示，打开聊天后清除；自己发送和重复快照不重复累计。双方更新或升级独立房间服务后可按发送者身份准确判断。官方 QQ／网易云聊天消息尚未接入，不会假装支持官方 App 消息提醒。

本次通过 617 项 Vitest、94 项 Node 测试、node／web 类型检查、ESLint、格式检查和生产构建。Xvfb 隔离实例与真实 WebSocket 听友验证了未读红点、打开后清除、自发消息回显及退出清理。密钥轮换、退房失败与晚到响应使用真实 IPC 处理器和模拟官方响应验证；未把用户正在使用的 QQ 房间拿来做破坏性测试，Windows 双账号实机回归仍待补充。

## 自动构建与发布

固定下载入口：[增强版 Releases](https://github.com/baek-nanxun/SPlayer-Next/releases)，构建进度见 [Actions](https://github.com/baek-nanxun/SPlayer-Next/actions)。

- 正式版：提高 package.json 的版本号并推送到 dev，Release 工作流完成检查、测试、六个平台／架构的原生构建、安装包与更新清单校验后，自动创建版本标签并公开发布。已经公开的版本不会被删除或替换，后续发布请提高版本号
- 手动正式版：Actions → Release → Run workflow，选择 dev，tag 留空即可发布当前版本；也可填写与 package.json 一致的已有 v* 标签。直接推送 v* 标签也支持
- Nightly：普通源码改动推送到 dev 后自动发布到固定 nightly 版本页；每天凌晨 2 点也会检查新提交，无新提交则跳过。版本号变更由正式发布流程处理，避免同一推送重复编译。Nightly 使用下一补丁版本号，例如稳定版 1.2.2 对应 1.2.3-nightly.*，确保更新器能够发现。应用设置选择 Nightly 通道后才会接收测试版
- 平台：Windows x64／arm64、macOS x64／arm64、Linux x64／arm64。Linux 提供 deb、AppImage 等格式。GitHub 编译成功不代表各平台都完成了人工功能测试；macOS 安装包未签名、未公证
- 只有全部构建成功才公开正式版，并附带 SHA256SUMS.txt。失败时查看 Actions 中的具体步骤，修复后提高版本号或重跑尚未发布的任务

工作流使用 GitHub 自动提供的 GITHUB_TOKEN，不需要把个人访问令牌、音乐账号 Cookie 或本机数据库放入仓库。首次 Fork 时需在 Actions 页面启用工作流。构建目录和安装包保存在 Actions／Releases，不提交到 Git 源码历史。
